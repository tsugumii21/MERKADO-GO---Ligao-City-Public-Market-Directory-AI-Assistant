# Part 4 — Firebase & Data Models

## Firebase Services Used

| Service | Package | Status | Purpose |
|---------|---------|--------|---------|
| **Firebase Auth** | `firebase_auth` | ✅ Active | Email/password registration, login, email verification, password reset |
| **Cloud Firestore** | `cloud_firestore` | ✅ Active | Main database — stores stalls, users, reports, usernames |
| **Cloud Messaging (FCM)** | `firebase_messaging` | ⚠️ Stub only | Push notification skeleton exists but is NOT fully implemented yet |

Firebase is initialized in `lib/main.dart` using `firebase_options.dart` (auto-generated by FlutterFire CLI).

## Firestore Collections

### Collection: `users`

Stores all registered user profiles.

| Field | Type | Example | Description |
|-------|------|---------|-------------|
| `uid` | string | `"abc123xyz"` | Firebase Auth user ID (also the document ID) |
| `username` | string | `"juandelacruz"` | Unique display username |
| `fullName` | string | `"Juan Dela Cruz"` | Full name for profile display |
| `email` | string | `"juan@email.com"` | Email used for registration |
| `profilePhotoUrl` | string? | `"https://res.cloudinary.com/..."` | Cloudinary URL or null if no photo |
| `role` | string | `"user"` or `"admin"` | Determines which portal they see |
| `favoriteStalls` | array\<string\> | `["stall_001", "stall_002"]` | List of favorited stall IDs |
| `fcmToken` | string? | `"..."` | Push notification token (unused currently) |
| `createdAt` | timestamp | `2026-07-15T10:00:00Z` | Account creation date |

**Document ID**: Firebase Auth `uid`

**Access Rules**:
- Users can read/update their own document
- Admins can read all documents
- Unauthenticated read allowed for email lookup during sign-in

---

### Collection: `usernames`

A lookup table for checking username availability and resolving username → uid during sign-in.

| Field | Type | Example | Description |
|-------|------|---------|-------------|
| `uid` | string | `"abc123xyz"` | The user's Firebase Auth ID |
| `createdAt` | timestamp | `2026-07-15T10:00:00Z` | When the username was claimed |

**Document ID**: `username.toLowerCase()` (e.g., document `"juandelacruz"`)

**Why this exists**: Users can sign in with **either their email or username**. This collection lets us look up a username → find the user's email → authenticate with Firebase Auth.

---

### Collection: `stalls`

All market stalls (the core data of the app).

| Field | Type | Example | Description |
|-------|------|---------|-------------|
| `stallId` | string | `"stall_001"` | Auto-generated unique ID |
| `name` | string | `"Aling Maria's Vegetables"` | Stall display name |
| `category` | string | `"Vegetables"` | Primary category |
| `categories` | array\<string\> | `["Vegetables", "Fruits"]` | All categories (multi-category support) |
| `products` | array\<string\> | `["Cabbage", "Tomato", "Onion"]` | Products sold (used by AI search) |
| `address` | string | `"Section A, Stall 12"` | Physical location description |
| `photoUrls` | array\<string\> | `["https://res.cloudinary.com/..."]` | Cloudinary image URLs |
| `openTime` | string | `"06:00"` | Opening time (24h format) |
| `closeTime` | string | `"18:00"` | Closing time (24h format) |
| `daysOpen` | array\<string\> | `["Monday", "Tuesday", ...]` | Operating days |
| `latitude` | number | `13.1458` | GPS latitude for map marker |
| `longitude` | number | `123.7278` | GPS longitude for map marker |
| `isActive` | bool | `true` | Whether stall is visible in directory |
| `status` | string | `"open"` or `"closed"` | Current operating status |
| `section` | string? | `"A"` | Market section identifier |
| `updatedAt` | timestamp | `2026-08-01T08:00:00Z` | Last edit timestamp |
| `tags` | array\<string\> | `["fresh", "organic"]` | Searchable tags |

**Document ID**: Auto-generated

**Access Rules**:
- All authenticated users can read
- Only `role: "admin"` can create, update, or delete

**Firestore Index**: Composite index on `isActive` ASC + `name` ASC (for filtered queries)

---

### Collection: `reports`

User-submitted stall reports (wrong info, closed stall, etc.).

| Field | Type | Example | Description |
|-------|------|---------|-------------|
| `reportId` | string | `"rpt_abc123"` | Auto-generated unique ID |
| `userId` | string | `"user_xyz"` | Who submitted the report |
| `stallId` | string | `"stall_001"` | Which stall is being reported |
| `stallName` | string | `"Aling Maria's Vegetables"` | Stall name snapshot (for display) |
| `description` | string | `"This stall moved to Section B"` | User's report text |
| `status` | string | `"pending"` | Report lifecycle: `pending` → `reviewed` → `resolved` |
| `createdAt` | timestamp | `2026-08-10T14:30:00Z` | When report was submitted |

**Document ID**: Auto-generated

**Status Lifecycle**:
```
pending  ──(admin reviews)──→  reviewed  ──(admin resolves)──→  resolved
                                                                    │
                                                          (admin can delete)
```

## Stall Open/Closed Logic

The app determines if a stall is currently open using **Philippine Standard Time (UTC+8)**.

Logic is in `lib/core/utils/stall_utils.dart`:

1. Get current time in UTC+8
2. Check if today's day name is in `stall.daysOpen`
3. Parse `stall.openTime` and `stall.closeTime` as `HH:mm`
4. If current time is between open and close → **Open** (green badge)
5. Otherwise → **Closed** (red badge)

This runs on the client side for real-time display.
